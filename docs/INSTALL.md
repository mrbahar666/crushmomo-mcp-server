# Crush Momo MCP — Install / Connect, per client

You need exactly two things: the MCP URL and a token.
URL: `https://mcp.crushmomo.com/mcp` — Admin (tokens + logs): `https://mcp.crushmomo.com/admin`
Token: generated by the owner from the admin panel, per client name
(e.g. Claude, Codex, ChatGPT). It is shown once. Store it in your own config
only — never in chat, code, or a repo.

After any method below, prove the connection with `ping` (see "Test" at the end).
If `ping` returns 401, the token is missing, expired, or revoked — get a fresh
token from the admin panel, do not paste tokens into chat.

## Muse

1. Copy this repo's `SKILL.md` into your skills folder (or read it from the repo).
2. Register the connector as `custom.crushmomo-mcp` with host `mcp.crushmomo.com`,
   Streamable HTTP, URL `https://mcp.crushmomo.com/mcp`, Bearer token from your
   secure connection flow (never a raw token in a file).
3. Test with `ping`.

## Claude Code (CLI)

```bash
claude mcp add --transport http crushmomo-mcp https://mcp.crushmomo.com/mcp \
  --header "Authorization: Bearer $CRUSHMOMO_MCP_TOKEN"
claude mcp list
```
Or project config (token via environment variable only, see `clients/.mcp.json`):
```json
{"mcpServers":{"crushmomo-mcp":{"type":"http","url":"https://mcp.crushmomo.com/mcp","headers":{"Authorization":"Bearer ${CRUSHMOMO_MCP_TOKEN}"}}}}
```
Claude Desktop: Settings → Developer → Edit Config, add the same `mcpServers` entry, restart.

## Codex (CLI / app)

In `~/.codex/config.toml`:
```toml
[mcp_servers.crushmomo-mcp]
url = "https://mcp.crushmomo.com/mcp"
bearer_token_env_var = "CRUSHMOMO_MCP_TOKEN"
```
Then export the token in your own shell (never in the repo):
```bash
export CRUSHMOMO_MCP_TOKEN="PASTE_YOUR_OWN_TOKEN_HERE"
codex mcp list
```
Or: `codex mcp add crushmomo-mcp --url https://mcp.crushmomo.com/mcp` and follow its login/token prompt.

## ChatGPT (OAuth — token-only from v1.0.2; Bearer alone does NOT work in the Plugins UI)

v1.0.1 bug, fixed in v1.0.2 (locally tested, see below): the OAuth token
INSERT used 4 placeholders for a 5-column table, so token issuance always
crashed, the code was already deleted, and ChatGPT showed
"authorization is invalid or has expired". v1.0.2 fixes the placeholders,
validates before burning the code, accepts JSON token bodies as well as
form bodies, and lets the approve page accept an admin token instead of a PIN.

1. In ChatGPT web: Settings → Apps & Connectors → enable Developer mode (paid plans; on
   Business/Enterprise an admin may need to allow custom connectors first).
2. Create a connector/app: name `crushmomo-mcp`, server URL `https://mcp.crushmomo.com/mcp`,
   authentication **OAuth**.
3. ChatGPT discovers the OAuth metadata from the server
   (`/.well-known/oauth-protected-resource/mcp` and `/.well-known/oauth-authorization-server`).
   It registers itself, then opens the server's approve page
   (`https://mcp.crushmomo.com/oauth/authorize`).
4. The owner enters the admin PIN **or** an admin token from /admin — either
   one alone is enough. ChatGPT receives a short-lived access token (1 hour)
   plus a refresh token (30 days). If the approve used a token, revoking that
   admin token also revokes the OAuth tokens issued from it.
   No Bearer token is pasted into the ChatGPT dialog itself.
5. Add the connector to a chat and test with `ping`.

### ChatGPT plugin ZIP upload (alternative to the MCP URL dialog)

Upload `plugin/crushmomo-mcp.zip` from this repo in ChatGPT → Plugins →
New Plugin (drag-and-drop, .zip). The ZIP contains exactly one plugin root:
`plugin.json` + `mcp.json` (remote server `https://mcp.crushmomo.com/mcp`)
+ `skills/crushmomo/SKILL.md`. No token, PIN, or secret is in the ZIP.
After upload, connect it the same way as above (approve with PIN or token).
Public directory publishing additionally needs OpenAI Platform verification
and review — the ZIP upload in your own Plugins page is not a public listing.

### GitHub URL install (Dots / local agents only)

Normal ChatGPT chat cannot install from a GitHub URL in chat — it cannot
change its own Settings. A local agent (Dots with its computer online,
Claude Code, Codex, Muse) can: see `plugin/README.md`. In short: clone
`https://github.com/mrbahar666/crushmomo-mcp-server`, set
`CRUSHMOMO_MCP_TOKEN` from /admin in the agent's own config (never in chat),
run `clients/stdio-wrapper.py` or use HTTP with a Bearer header, test `ping`.

## Groq (agent code — there is no Groq chat MCP button)

Groq's chat UI has no MCP connector button. Use Groq's model inside an
MCP-capable agent instead. See `clients/groq-example.py` (in this repo):
it runs an MCP client over Streamable HTTP with the Bearer token, calls
`ping` / `sales_summary`, and passes the tool result to a Groq model for
the final answer. You need a Groq API key for the model call itself — that
key is yours, never part of this MCP token.

## Any standard MCP client

Any client that supports remote Streamable HTTP MCP works with:
URL `https://mcp.crushmomo.com/mcp`, header `Authorization: Bearer <your-token>`.
If the client only supports stdio, use `clients/stdio-wrapper.py`:
```json
{"mcpServers":{"crushmomo-mcp":{"command":"python3","args":["/path/to/stdio-wrapper.py"],"env":{"CRUSHMOMO_MCP_TOKEN":"YOUR_TOKEN_IN_YOUR_OWN_CONFIG_ONLY"}}}}
```

## Test (prove it works)

Ask the agent: "Use crushmomo-mcp ping and tell me the server time."
A working connection returns `status: ok` and a Dhaka time. Then try a small
read-only call, e.g. `products_list` with `limit: 5`. If either returns 401,
the token is the problem, not the server code.
